Decisions

What we chose, when, and why. Read this before changing something that looks strange: it may be strange on purpose. Student votes go here too, with the count ("6 for, 9 against"). Replaced decisions stay, marked as replaced, so the history is readable. The D-numbers point to the project's own Docs/decisions.md.

Waiting for a vote

Real multiplayer, or solo with an AI crew?

Waiting for a vote

Friends crewing one tank together, or you and a crew of AI characters. The pitch assumes multiplayer, and the work so far keeps multiplayer working.

How serious should the game be?

Waiting for a voteOpened 2026 Nov 1

A scale from 1 (very sombre) to 10 (full cartoon silly). The average becomes the tone we aim for: in the writing, the characters, the sounds and the look.

A fixed map, or a dynamic map?

Waiting for a voteVote opened 2026 Nov 1

A fixed map is one hand-built world, the same every time: you learn its roads and landmarks, and a town a class builds stays for good. A dynamic map is put together differently each time or changes while you play: every trip is new, but good-looking places and stories are harder. The vote has a third choice: a mix, with hand-built towns and landmarks and generated land between them.

Which faction first?

Waiting for a vote

The Brass Parliament, the Neon Collective, the Church of the Scroll, the Rolling Villages, or a new one. Whoever builds first sets the template.

The arcade rig: now or later?

Waiting for a vote

A side project for the hardware-minded now, or a goal for when the game works. The idea.

Should the tank get stuck on its belly?

Waiting for a vote

Found in the comparison level: the simulated tank can get stuck on a rock with its belly, and then only turn. Real tanks do this too. Never, sometimes (with a way out), or yes, as part of the challenge? The idea.

How should decor turn?

Waiting for a vote

One turn key, two, or more snap points. The idea.

Decided, newest first

The fake-physics tank

2026 Nov 8Student vote

Choice: The tank drives with fake physics: a few simple springs and a drive force, not simulated wheels and suspension.

Why: It won the student vote. It is cheaper, it already works in multiplayer, and it is the one we have been building on for weeks. Early votes (2026 Oct 25): fake physics 5, simulated 3.

We stay on this Discord server

2026 Nov 8Student vote

Choice: The project keeps using the TrollByte Discord server.

Why: Students voted to stay.

Crews carry their own light

2026 Nov 8Design

Choice: Every crew member wears a headset with a head lamp, instead of lamps in every room of the tank.

Why: Dozens of lamps per tank cost too much. The headset also shows who is crew, and has room for a HUD and team talk. The idea.

Every named person is their own file

2026 Nov 8How we build

Choice: A named person (shopkeeper, mayor, quest giver) is saved as their own file. Background people are made in the level and get a random name.

Why: Students never edit the same file at the same time, and quests and saved games can point at a person, wherever they stand.

Armour gets real holes

2026 Nov 5Design

Choice: Shells cut real holes in tank and building pieces, shaped by the kind of shell, its size and the angle.

Why: Students and teachers picked it over dents and swapped damaged models.

Our editor tools are written in C++

2026 Nov 3How we build

Choice: Tools like the Terrain Stamp Maker are C++ in the project, not Python scripts.

Why: Unreal's own Python has no maths libraries, and installing them on every school computer would break easily. The C++ version needs nothing extra.

What a piece costs is in one table

2026 Oct 31DesignD-23

Choice: The build cost of every piece is in one table. Everything else about a piece stays with the piece itself.

Why: Costs are balance numbers that we compare across all pieces and change often while testing. One table shows them side by side.

Building is free in workshops and costs materials everywhere else

2026 Oct 31Design

Choice: In a workshop you build for free. Elsewhere a piece costs materials from your backpack and the tank; removing it gives them back, a destroyed piece drops 20 to 80 % of them, and repairing a destroyed piece costs them again.

Why: Designing should be free and fun; out in the world, building and repairing should be part of the game, and something we can balance.

Packs from outside stay untouched

2026 Oct 29How we buildD-22

Choice: We don't change files from packs we got from outside (like Epic's Game Animation Sample). We make a child of it, or a copy in our own folder, and use ours. The first step: our own game mode and player controller, used by every level.

Why: If a pack is updated or downloaded again, our changes inside it are lost, and it's hard to see what is ours.

The compiled C++ is shared

2026 Oct 26How we buildD-21

Choice: The built C++ module is committed with the code it was built from. Whoever changes C++ builds it and shares both.

Why: Students without Visual Studio could not open the project after the first C++. The shared build is small, about 1.5 MB. (This answers the question left open when C++ came in.)

The building plan is 3 × 3 m; half floor tiles only fill holes

2026 Oct 25Design

Choice: Rooms and walls follow the 3 × 3 m plan. Half floor tiles (1.5 × 1.5 m) are only for the holes that 1.5 m stairs, ladders and hatches leave, and walls on them line up with the walls on the full tiles. The low checkpoint wall is a barricade, not a room wall.

Why: 3 m stairs are too wide, so 1.5 m pieces leave holes next to them. Walls above those holes must be flush with the rest of the wall. There are no half-size rooms.

We call them pieces

2026 Oct 24How we build

Choice: Anything you place in build mode is a piece: floor tiles (full and half), edge pieces like walls, corner pieces, fixtures like stairs and control panels, and decor. What you build on is the build root, and a saved build is a design.

Why: "Block" made us think of Minecraft. One set of words in the game, the docs and our talk, for people and AI tools alike.

Three places for content

2026 Oct 22How we buildD-20

Choice: Packs from outside (GASP, Fab and other samples) stay in their own folders, and we copy things out of them, never into them. Developer folders are for testing. The project folder is for what works and belongs to the game.

Why: Our own files mixed into GASP's folders are hard to find, and easy to lose or break when a pack is updated.

C++ is part of the project

2026 Oct 22How we buildD-19

Choice: The project has its own C++ code, starting with the turrets. Blueprints are still the default for most things.

Why: Emil and Mikkel now write C++, with AI tools, and the turrets needed it. Still open: whether everyone builds the C++ part on their own computer, or we share it ready-built.

Hatches only if they really open and close

2026 Oct 17Design

Choice: No hatches that are just for show. They come later, and they must open and close.

Why: Players notice static things that look like they should move, and it annoys them. A hatch should matter: "Battle stations, close all hatches!"

Tank designs are saved from the tank, while driving, in single player

2026 Oct 17Design

Choice: The design library opens with L in the control box only. The picture is taken from the driving camera.

Why: You look at the tank from outside while driving, so that is the right view for its picture. Later it may only work in a Workshop level.

Grid lines every 75 cm on tank pieces

2026 Oct 17How we build

Choice: The greybox material on vehicle pieces draws a line every 75 cm and a thick line every 300 cm.

Why: Half-size pieces showed grid lines in the wrong place. 75 cm fits both full and half pieces.

In multiplayer, the host builds

2026 Oct 15How we build

Choice: Only the host builds and drives the tank; the pieces and the tank's position are copied to the other players.

Why: One version of the truth. When each machine built its own pieces, the pieces could not be named across the network.

A moving tank shoves you; it doesn't hurt you

2026 Oct 15Design

Choice: Standing in front of a moving tank pushes you out of the way. No damage, no animation.

Why: "A wall hitting you just pushes." Simple, and it can be revisited when the real tank exists.

One welded body for the whole tank

2026 Oct 15How we build

Choice: Every piece is welded to one body as it is placed. No body per floor, no special tricks.

Why: The stress test: 1183 welded pieces cost about 6 ms per frame, as long as each piece has overlap events switched off.

Play uses only the Mover character

2026 Oct 13How we build

Choice: The game spawns GASP's Mover character; the older CMC character stays in the project, unused.

Why: Epic is moving towards Mover, it is said to suit multiplayer best, and there are many tutorials for adding movement to it.

A building grid of 3 × 3 × 3 metres

2026 Oct 12DesignD-18

Choice: Every piece fits a 3 m cube grid, placed in steps of 1.5 m and turned in 90° steps. A floor is 50 cm thick.

Why: 3 m divides into halves, thirds, quarters, fifths and sixths in whole centimetres, matches the climb heights we tested, leaves room for thick armour beside a corridor, and is about one real storey.

Tanks drive on 6 to 8 wheels; the tracks are only for show

2026 Oct 9How we buildD-17

Choice: The tank is simulated on 6 to 8 wheels. The tracks you see are drawn over them.

Why: Six to eight wheels drive smoothly and stand still. Twelve wheels crept and turned by themselves. Simulating every track link is far too expensive.

Physics prediction is on for the whole project

2026 Oct 9How we buildD-16

Choice: A project-wide physics setting is switched on.

Why: Unreal's Chaos vehicles ignore all input without it.

The prototype uses one character size

2026 Oct 9DesignD-12, D-15

Choice: The prototype is built for the normal 172 cm character. Races of other sizes are parked; if they come, keep them close to 172 cm.

Why: Climbing at other sizes works but the hands don't meet the edge. Fixing that properly is a week or more, and the focus is the tank. The idea.

Shared test levels for tests worth repeating

2026 Oct 9How we buildD-14

Choice: Tests we want to run again get their own level in a shared test folder.

Why: Changes to come, like a bigger character or a jump jet, must be checked against the same tests.

The classic camera is the default

2026 Oct 9DesignD-13

Choice: A spring arm behind the character, not GASP's new camera rig.

Why: In tight corridors that move, the classic camera stayed calm and the new rig jumped around. Tight spaces that move are the core of a tank game.

Tests and temporary work stay in your developer folder

2026 Oct 7How we buildD-11

Choice: Test maps and throwaway assets go in your own developer folder, for people and AI tools alike.

Why: Otherwise the shared folders fill up with test maps with random names.

One greybox material, with a switch for moving things

2026 Oct 7How we buildD-10

Choice: Moving things use the same material as the level, with a tick box that sticks the grid to the object.

Why: One material to keep correct, and the colours come from the same settings.

Every mesh is climbable by default

2026 Oct 6How we buildD-06

Choice: Every mesh can be climbed or vaulted unless it is tagged NoTraverse.

Why: Hiding a special climbable block inside every mesh is too much work and too easy to forget when a whole class is greyboxing.

One set of documents for people and AI tools

2026 Oct 6How we buildD-08

Choice: Plain documents in the project's Docs folder, written for people.

Why: Students connect many different AI tools. Two versions of the same text drift apart.

AI tools work through Unreal's MCP, not by taking over the screen

2026 Oct 5How we buildD-07

Choice: An AI tool drives the editor through Unreal's MCP plugin, not the mouse and keyboard.

Why: The computer must stay usable for the person while the AI works.

The greybox grid is a ruler, measured in the world

2026 Oct 5How we buildD-03

Choice: The greybox material draws its grid from world position: a line every metre.

Why: The grid must show true size on any mesh at any scale, so jump heights and door widths can be read off the wall.

Diversion for version control, not GitHub

Before 2026 Oct 5How we buildD-09

Choice: The project lives in Diversion.

Why: GitHub timed out eight times in a row pushing this project. An Unreal project is many gigabytes of files that Git handles poorly.

Built on GASP, in Blueprints

Before 2026 Oct 5How we buildD-01

Choice: The project starts from Epic's Game Animation Sample in Unreal Engine 5.8, with no C++.

Why: A finished, good-looking character with movement and climbing from day one. C++ will come when students who learn it join. (It came on 2026 Oct 22.)
